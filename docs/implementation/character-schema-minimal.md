# 最小 Character Schema 六字段实施计划

状态：2026-09-18 已完成并验证。隔离 PostgreSQL schema 的 migration 升级/回滚回归、41 项后端测试、Alembic 一致性、诊断与 Ruff 均通过。

## 目标与范围

用六个可独立填写的字段表达版本化角色设定，接通现有文字链路，为下一步 Memory System 设计提供稳定输入。只实施一个阶段，不扩展角色资料采集、完整 Canon、自动记忆、关系变化、语音或前端编辑器。Memory System 完成后再优化字段结构与内容。

## 建议的数据结构

保留 Character、CharacterVersion、CharacterInstance 三层。六字段属于 CharacterVersion 的角色定义，以可空 JSONB 列 `definition` 保存；不是直接加到 `characters` 身份表。

当前先让六个字段的值都是文本，不继续展开子字段、称呼映射或算法。`definition` 固定包含 `schema_version: "1.0"` 和六个字段，拒绝未知键和非字符串值；允许五个非身份字段留空表示尚未确认，但 `identity` 不可为空。所有文本统一 trim 并压缩连续空白，空内容不编入提示词。

| 字段 | 内容 | 边界 |
| --- | --- | --- |
| `identity` | 身份背景、身份角色 | 不保存用户私人信息 |
| `personality` | 核心性格、价值观 | 不保存本轮情绪 |
| `speaking_style` | 默认语气、称呼和表达习惯 | 后来形成的称呼变化由实例数据表达 |
| `behavior` | 交流方式、自主立场、角色特有边界 | 不展开行为评分或情绪分支 |
| `worldview` | 所处世界、角色对跨世界交流的理解 | 沿用 V1 基线，不重新决定通信前提 |
| `relationship_premise` | 用户身份映射、原作初始关系 | 不保存相处后形成的信任和亲近 |

`id`、`character_id`、`checkpoint`、`system_prompt` 保留。Character Definition Schema Version 为 `1.0`，Prompt Builder Version 为 `1.0`。`source_work`、`aliases`及完整资料树暂缓；此阶段只落地固定六文本字段，不将旧草稿的其他建议一并采纳。

## 导入与提示词接入

1. 新角色包提供 `definition`，由独立校验模型检查六字段。
2. 独立 Prompt Builder 按固定顺序生成角色提示词，组合已确认的通用角色规则与非空设定。规则沿用 V1 基线，不新增产品行为；不将记忆或状态写入角色定义。
3. 导入时将六字段和生成的 `system_prompt` 一起保存。六字段为结构化版本的设定来源，`system_prompt` 是冻结的派生结果；结构化输入不允许同时另填一份提示词。
4. 聊天继续读取版本的 `system_prompt`，复用现有 ContextAssembler 的记忆、状态和历史组装顺序。此阶段不要求改 API 返回或前端角色配置。
5. 重复导入校验六字段和编译结果不可变；修改设定或编译规则导致结果变化时必须建立新版本，不覆盖旧版本。未来编译器调整需要显式版本更新。

## 旧版本和内容处理

- 迁移只增加可空 `definition` 列，旧记录保持 null，原提示词、实例版本引用、聊天及记忆保留。
- 旧角色包继续接受纯 `system_prompt`，不自动从自由文本推断六字段，不自动升级已有实例。
- 工程测试角色增加独立的新结构样例，验证六字段能够导入并实际成为 Provider 输入；保留旧包验证兼容。
- 三位主角色继续使用已有联调版本，不在本阶段补写正式性格或未知关系。其结构化内容迁移另行处理，不作为 Memory System 设计的前置条件。

## 实施顺序与验收

已完成模型与迁移、六字段校验及 Prompt Builder、导入兼容与新结构工程样例、测试和文档同步。提交由用户另行决定。

验收条件：

- 数据库能保存固定六字段；缺键、额外键、非法类型与空身份被拒绝，待定字段可留空。
- 新结构导入后的 Provider 输入确实包含相应设定；六部分顺序固定，留空部分不编造内容。
- 同版本重复导入幂等，变更设定被拒绝，新版本可导入；已有实例继续引用旧版本。
- 旧包和旧会话正常工作；个人记忆、状态和历史仍归实例，角色定义不吸收运行数据。
- 隔离 PostgreSQL schema 验证迁移升级、回滚及旧数据保留；执行相关后端回归与 Ruff。使用 fake Provider，不调用真实模型。
- 更新角色模块、记忆接口边界和当前状态；达到验收后停止本阶段，交由用户开始 Memory System 设计。

仅启动必要测试依赖，测试结束停止本任务启动的服务，不关闭用户原有服务或删除持久化数据。
