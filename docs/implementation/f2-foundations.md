# F2 基础能力完善：五阶段实施方案

## 授权与执行方式

用户授权 Agent 起草可执行方案并连续完成 A–E：每阶段实现、验证、复查通过后单独 commit，再执行下一阶段。本方案是此次委托采用的实现方案，不将可替换实现参数升级为永久产品规则。不 push，不部署公网。

初始版本：fece84f，工作区干净。测试使用独立 PostgreSQL schema 与 fake 文本 Provider，不调用付费模型，不改默认用户资料。仅启动必要本机测试依赖，每阶段验收后停止本任务启动的服务。若依赖原本已由用户启动，保留其运行状态。

性格调整、角色资料库、正式 Canon、个性化按钮、TTS、登录、云同步、向量检索、自动记忆提取、长对话摘要和关系评分算法均不在本轮。保留现有已认可视觉，新增管理操作沿用轻量控件。

## 阶段 A：会话与历史

输入：现有会话和消息。输出：带真实时间、分页与定位的历史，可恢复旧角色版本会话。

- 为新会话和新轮次记录 UTC 创建时间；旧数据时间保持 null，页面标明未记录，不使用迁移时间冒充历史。
- 新增分页历史目录和单会话元信息接口，包含 character_id、version_id、instance_id、checkpoint；原列表和消息接口保持兼容。
- 历史按最近活动排序，稳定 ID 作为同时间次序；提供轮次定位。
- 前端依据角色身份选择主题，依据会话绑定版本继续聊天；刷新保持会话及版本，不自动升级 Canon。
- 列表翻页失败保留已加载项目；旧版本恢复不得混入当前会话草稿或尚未完成的请求。

| 验收输入 | 预期结果 | 证据 |
| --- | --- | --- |
| 新旧数据迁移、回滚再升级 | 原消息保留，旧时间未知，新时间真实 | 独立 schema 迁移测试 |
| 多会话、同时间、翻页和定位 | 顺序稳定、来源轮次可定位 | API / 浏览器测试 |
| 其他用户访问、旧版本恢复、加载失败 | 404 隔离、继续原版本、失败不清空 | API / 浏览器测试 |

## 阶段 B：个人记忆数据与管理

输入：用户明确选择保存的消息或手动填写的个人信息。输出：可查看、保存、纠正、删除和定位来源的实例级个人记忆。

- 每条记忆归属实例，内容、事实/推测标记、可选来源消息、版本号、时间；来源必须来自同实例成功轮次。
- 用户主动保存入口，不自动从对话提取；当前不会自行生成推测记录，类型边界为未来提取预留。
- 创建使用请求 ID 幂等；纠正/删除使用版本检查，避免旧页面覆盖新编辑；同实例写入串行化。
- 删除保留不含原内容的墓碑与来源标识，用于防重复创建和后续上下文排除；原始聊天保留。
- 纠正或删除后，来源轮次及此前可能引用旧信息的对话在后续模型上下文中按实例修订边界排除；C 接通。不能承诺清除原始聊天、已有回复或模型自身知识。
- 前端接通列表、空白、失败、创建/编辑、删除确认、来源跳转。明确手动保存机制，不伪装自动记忆。

| 验收输入 | 预期结果 | 证据 |
| --- | --- | --- |
| 重复创建、并发纠正、删除后重试 | 单条创建、冲突409、不会复活 | API 并发测试 |
| 跨用户/实例来源 | 拒绝且不暴露其他内容 | API 测试 |
| 保存/纠正/删除/来源页面操作 | 成功持久化，失败保留编辑，原聊天仍在 | 浏览器测试 |

## 阶段 C：上下文与回复契约

输入：版本化角色定义、成功历史、当前有效记忆、可选状态。输出：框架无关、可检查的上下文和兼容旧接口的文字回复。

- 从 Repository 拆出纯上下文组装模块，明确顺序和容量，默认最近12成功轮不变；记忆按明确、可配置的条数/字符上限装入，不引入 Embedding。
- 事实与推测显式标记，作为数据呈现，不把用户内容提升为系统指令；缺少记忆/状态时继续文字链路。
- 有效记忆可跨同实例会话使用；纠正/删除的修订边界屏蔽旧上下文，原历史仍可浏览。
- 轮次保留上下文修订号。模型调用期间记忆变动则阻止旧结果提交，返回可重试错误；不保存完整提示词或内部分析。
- Character Response 保持现有文字与音频占位契约，可替换扩展独立于 Provider，暂不制造情绪或记忆候选。

| 验收输入 | 预期结果 | 证据 |
| --- | --- | --- |
| 成功/失败历史和有效记忆混合 | 顺序与上限正确、失败轮和已删除内容不进入 | 纯函数与服务测试 |
| 模型等待时纠正或删除 | 旧上下文结果不提交，重试使用最新信息 | 阻塞 Provider 并发测试 |
| 重复已完成请求、空记忆 | 回复稳定、普通文字仍可用 | 回归测试 |

## 阶段 D：状态与关系存储边界

输入：内部策略提交的、有已完成轮次依据的状态事件。输出：实例级当前状态与事件依据，供 C 的可选输入读取。

- 短期交流状态与关系描述分开，采用可选描述字段，不设置好感度分值和自动涨跌公式。
- 内部服务负责来源校验、请求幂等、预期修订号检查、事件与快照原子保存；无面向用户的内部状态/评分 API。
- 暂无自动更新策略，因此普通聊天不凭空生成状态；独立服务和集成测试验证真实写入后能参与后续上下文。
- 记忆纠正/删除时清除可能依赖旧内容的当前状态并排除旧事件，避免通过状态重新引入；不改角色核心性格。

| 验收输入 | 预期结果 | 证据 |
| --- | --- | --- |
| 内部事件、重复事件、旧修订、错误来源 | 原子写入、幂等或冲突、不越界 | 服务及并发测试 |
| 新状态后的聊天、重启 | 状态能被读取，持久化有效 | 上下文集成测试 |
| 记忆纠正/删除、公共接口检查 | 旧状态不再使用，无内部评分泄露 | 集成/API 测试 |

## 阶段 E：维护与排障

输入：本地工程环境与测试命令。输出：不泄露密钥/私聊的诊断与可重复验证入口。

- 增加只读诊断命令：配置是否齐全、数据库/迁移是否可用；不输出密钥、完整连接串、提示词或消息内容。
- 请求关联 ID 与安全错误日志，便于定位故障；不记录请求正文，不引入分析面板。
- 提供本地验证入口和运行/停止说明，子进程有超时与 finally 清理，复用用户服务时不误关闭。
- 最终整合测试、迁移与回滚检查、文档同步；不新增清库、自动备份删除或部署操作。

| 验收输入 | 预期结果 | 证据 |
| --- | --- | --- |
| 缺少密钥、数据库不可用、模型错误 | 可定位且脱敏，无自动真实调用 | 诊断与日志测试 |
| 成功/失败验证命令 | 返回可靠退出码、清理自启进程 | 本地验证 |
| A–D 全链路回归 | 相互兼容，数据隔离成立 | 全套后端、前端、迁移检查 |
