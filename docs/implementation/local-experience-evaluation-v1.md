# 本机真实对话评测 V1（2026-10-21）

本轮目标是用可重复的虚拟用户场景检查现有记忆、跨会话连续性、隔离与三位正式角色的回复。评测调用真实 DeepSeek，但只写入临时 PostgreSQL `eval_*` schema；每次结束自动删除。没有导入或修改默认用户的聊天、记忆和角色实例，也没有修改正式 CharacterVersion。

## 输入与运行

- 记忆及对话场景：`fixtures/runtime_evaluation.json`，执行入口 `scripts/evaluate_runtime.py`。可用 `--version-id nanally-canon-p22-v1` 将同一套场景放在正式娜娜莉版本下运行，`--only <场景 ID>` 可限制调用量。
- 角色体验场景：`fixtures/character_experience_v1.json`，执行入口 `scripts/evaluate_character_experience.py`。使用 P22 角色定义和 Prompt Builder 1.0；不创建数据库实例。自动检查只覆盖明确事实和禁用行为，正文另存 `.local-run/character-experience-v1.md` 供人工审阅。
- 完整调用分别为 `uv run python -m scripts.evaluate_runtime --profile deepseek --version-id nanally-canon-p22-v1` 和 `uv run python -m scripts.evaluate_character_experience --profile deepseek`。报告位于未跟踪的 `.local-run/`，包含虚拟用户正文，不应作为公开日志提交。

## 结果

在加入“明确忘记”场景前，正式娜娜莉版本的记忆与对话全量回放为 **30/30 检查通过，34 次 Provider 调用**：稳定偏好、假设身份过滤、明确纠正、事件更新、跨用户隔离、20 轮后的分段摘要和新会话续聊、显式记住与未来站内提醒均通过。随后单独增加的同用户跨角色实例隔离检查通过。

三位角色的 **10/10 自动硬检查通过，10 次 Provider 调用**。人工阅读发现伊洛伊在日常水果话题中说“我陪福利院的孩子出门时也见过大人这样挑”。P22 定义支持她曾在福利院做志愿者，却没有这次具体出行的依据；这是把背景推成亲历事件的风险。该场景另有两个问句的软提示。其余样本未发现同级别的人设/边界问题；10 个样本不足以证明长期角色稳定性。

新增的**明确忘记**场景连续两次失败。用户先要求记住“喝咖啡不加糖”，再明确要求忘记。结构化对话决策校验失败并降级为普通回复，`remember` effect 已提交，`forget` effect 没有提交。随后后台提取将“要求撤回口味偏好”重新写成有效记忆；一次重跑还在新会话的上下文与回复中直接出现“不加糖”。因此不能宣称当前真实模型链路满足“忘记后不再引用”。评测现在要求 `forget` effect 必须提交、有效记忆数归零、旧内容不进入新上下文或回复；此用例保持失败以供修复回归。

本轮没有改动对话/记忆业务规则。下一个修复阶段需要检查忘记命令的结构化输出/校验降级，以及后台提取对撤回指令的处理；修复后优先单独复跑 `explicit-forget`，再跑全部场景。

## 验证与边界

- 后端 `uv run pytest -q -p no:cacheprovider`：159 passed，3 个现有依赖/迁移警告。
- `uv run ruff check .`：通过。
- 评测结束后 `eval_*` schema 数为 0；未调用前端，没有更改数据库迁移。
- 本轮用的是真实模型，输出存在波动；自动关键字检查不能替代人工判断，也没有覆盖长期多周试聊或主动离线通知。

## 2026-10-21 定向修复与复验

真实模型原始输出确认：忘记命令的目标 ID、revision 正确，但模型把被删除的文字写入 `content`，触发严格校验失败。现在输出说明明确要求 `forget.content=null`，校验规则仍保持严格；校验失败的日志只记录错误字段路径，不记录用户正文。后台自动提取在明确忘记/删除请求上直接跳过，并在提取说明中禁止把“已撤回”等元描述另存为有效记忆。删除操作本身仍由领域服务按实例、目标和 revision 校验。

角色侧只将运行时 Response Policy 从 1.0 更新为 1.1，限制把概括背景扩写成具体亲历；不回写已有 CharacterVersion。伊洛伊原失败场景单独真实复跑时未再编造福利院出行，但仍触发两个问句的软提示。该句现列入自动禁用短语和人工复核点；一次复跑不能证明此类生成错误完全消失。

- 真实模型 `explicit-forget`：8/8 检查通过、4 次 Provider 调用；`remember` 与 `forget` 均提交，有效记忆数为 0，新会话上下文与回复未含旧口味。
- 真实模型纠正、忘记、记住/提醒及跨用户/跨角色隔离定向回归：19/19 检查通过、18 次 Provider 调用。
- 后端全套 161 passed（3 个既有警告），Ruff 通过；没有新 migration、前端改动或默认用户数据写入。全量真实模型长聊场景未重复调用，本轮复验集中在受影响的操作与角色回复。
