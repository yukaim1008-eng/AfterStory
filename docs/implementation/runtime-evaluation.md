# 对话与记忆真实模型评测

状态：2026-09-27 完成第一轮可重复真实模型验收。

## 范围

本轮使用独立 PostgreSQL schema、工程测试角色和虚拟用户验证现有文字聊天与 Memory System。评测不写入默认用户数据，不修改正式角色资料；每次运行结束自动删除临时 schema，原始报告保存在未跟踪的 `.local-run/runtime-evaluation.json`。

固定样本位于 `fixtures/runtime_evaluation.json`，执行入口为：

```powershell
uv run python -m scripts.evaluate_runtime --profile deepseek
```

可以用 `--only explicit-correction` 等参数单独回归某个场景。

## 覆盖场景

- 四个虚拟用户分别覆盖稳定事实与偏好、假设不污染现实身份、明确纠正旧事实，以及同一事件的后续进展。
- 两个额外用户验证跨用户及跨实例隔离。
- 预置 20 轮阅读角对话，真实生成分段摘要，并在新 Conversation 中验证续聊。
- 创建一条已到期事项，验证站内提醒领取与确认送达。
- 检查 Character Prompt、检索后的 Memory、连续性摘要和当前消息确实进入 Provider 输入。

## 首轮发现与修复

1. 结构化 Provider 只给出内部模型名称，没有提供 JSON 契约。真实模型会返回合法但不兼容的自定义结构。现已提供完整 JSON Schema，并在 DeepSeek 请求中启用 JSON Object 模式。
2. 20 轮摘要使用普通聊天的 1024 token 输出上限，会返回不完整结果。现将结构化抽取限制为 2048，摘要限制为 4096，不改变普通角色回复上限。
3. 自动提取没有读取同实例的已有记忆，因此无法引用目标执行明确纠正。现向提取器提供最多 50 条当前有效候选，并校验模型只能引用输入中的 memory ID。
4. Event 候选的 `scene` 与事实候选的 `scope` 在共同校验器中混用，且提取输入缺少消息时间。现已按 payload 类型读取场景，传入服务端记录时间与时区，并让事件补充保留原发生时间、追加新进展和来源版本。

## 最终结果

- 真实模型检查：26/26 通过。
- Provider 调用：30 次，其中聊天 15 次、结构化任务 15 次。
- 最终全量回放没有结构化任务重试。
- “杭州 → 明确说错 → 苏州”形成不可变新版本；运行时上下文和回复只使用苏州。
- “9 月 20 日与小周发生排班争执 → 9 月 27 日已经说开”保持为一条记忆和两个不可变版本，原发生时间与后续进展均被保留。
- 20 轮摘要保留“银杏书签”、开放日、分工及尚未联系陈老师的未完成事项，新会话能够自然接续。
- 评测结束后没有遗留 `eval_*` schema，也没有启动或停止用户的 Docker 服务。
- 仓库回归：Ruff 通过，71 项后端测试通过；前端生产构建与 32 项 Playwright 在本轮完整验证中通过。Alembic 保持 `m7_state_relationship (head)`，本轮没有新增迁移。

## 当前结论与边界

这次结果证明当前工程角色上的聊天、自动记忆、纠正、摘要、召回、隔离和站内提醒可以组成可用链路，但不等于长期主观体验已经完成。当前未配置 Embedding Provider，召回实际使用全文与近期候选降级；正式三位角色仍是联调资料；普通聊天中的“记住、忘记、设提醒”还没有统一的意图编排与操作回执入口；State/Relationship 的内部演进服务尚未接入普通聊天 Provider 输出。这些应进入 Conversation Core v1，而不在本评测阶段扩展 Memory Schema。
