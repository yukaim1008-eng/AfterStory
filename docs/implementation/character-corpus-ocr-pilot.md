# 人物资料研究库：画面字幕 OCR 试跑

状态：P1 的五分钟本地试跑已完成，并已据此实现整集处理工具；完整 P1 结果见 [剧情视频本地处理工具与 P1 验证](character-video-pipeline.md)。

## 试跑范围

- 来源：`BV1kqoaBiEVZ` P1《第0话 不虞亦先兆》。
- 片段：原视频 `05:00–10:00`，精确时长 300 秒，1920×1080、30fps，含原音频。
- 原始缓存：B 站桌面端保存在 `%USERPROFILE%\Videos\bilibili\37739368085`。
- 本地结果：`research/character-corpus/local/ocr-pilot/BV1kqoaBiEVZ-p01/`，受 `.gitignore` 排除，不提交视频、截图或逐字稿。

B 站缓存把视频和音频保存为两个 `.m4s` 文件，并在标准 MP4 数据前增加 9 字节客户端标记。本次只读取原缓存，临时去掉标记后合并分轨；临时完整副本已清理，B 站原缓存未修改。

## 试跑方法

1. 使用 FFmpeg 7.1 合并视频与音频，并重新编码边界，得到准确的五分钟片段。
2. 只裁剪 1080p 画面底部居中的字幕带，避开 UID 和大部分战斗 UI，再放大两倍。
3. 使用 PaddleOCR 3.7.0、PP-OCRv5 mobile detection/recognition 和 PaddlePaddle 3.3.1 在 CPU 本地识别；Windows 下关闭 MKLDNN 以绕过 oneDNN 的模型兼容错误。
4. 对对白较密集的后半段每 2 秒取样，以相邻文本相似度合并重复帧。所有模型调用均在本机完成，没有调用云端视觉或语言模型。

## 结果

- 五分钟片段前约两分钟仍以战斗和无对白过场为主，约七分钟处开始出现较连续的画面字幕。
- 试跑产生 47 个含中文文本的采样帧，时序合并后得到 21 个候选片段。
- 清晰完整帧上的正文识别稳定。例如“刚刚好的角度？这么绝佳的观景点，你是怎么找到……”正文置信度为 0.9984；包含 `beat`、`freestyle` 和 `aka` 的中英混合字幕也能识别。
- 专有名词“极漩”“泯除”“奇点”等在本片段中能够识别。高置信正文通常可直接进入人工复核草稿。
- 当前数字只能说明技术可行，不能当作整集召回率或准确率；本次没有制作完整人工真值集。

已观察到四类必须处理的误差：

1. 首尾省略号、引号、破折号容易被省略或混淆，偶尔出现繁简混写。
2. 逐字显示中的中间帧会形成残句；应等待字幕稳定后取最长文本。
3. 固定间隔采样可能漏掉停留不足两秒的短句，也会重复识别长句。
4. 电影式过场常只有台词而没有说话者姓名；OCR 可以取得文本，但不能仅凭字幕可靠归属角色。带姓名标签的普通对话界面可同时识别标签，仍需场景级复核。

## 对完整剧情处理的结论

画面字幕 OCR 可作为这套 22 小时录像的文本入口，并且不需要把视频帧发送给大模型。合理的批处理链路是：

```text
本地视频规范化
→ 字幕区域与界面类型检测
→ 高频轻量检测字幕变化
→ 只对稳定且变化后的帧执行 OCR
→ 相邻结果去重、补全与时间范围合并
→ 说话者和场景复核
→ 只把去重后的场景文本交给模型提取人物证据
```

这样 Token 只消耗在已经压缩过的场景文本和人物证据整理上，不会按视频帧消耗。以上批处理边界已经在 Version `1.0` 工具和完整 P1 上实现并验证；当前仍不生成 Traits 或 Character Definition。
