# 剧情视频低成本审核工具与 P2 实验

状态：完成。

## 实现

视频工具新增低成本审核协议 Version `1.0` 与 Prompt Version `1.1`：

1. `low-cost-pack` 按时间范围生成带输入哈希的紧凑包；
2. 轻量模型只读取包内文本和被风险规则选中的图片；
3. `low-cost-validate` 严格校验响应并分出自动候选和疑难队列；
4. `low-cost-benchmark` 只在已有人工稿的校准数据上计算一致率；
5. 所有产物继续位于 Git 忽略的本地 staging，不覆盖正式审核文件。

PowerShell 入口也按命令加载依赖：只有完整 OCR 才安装 Paddle，审核报告/联络表只加载 OpenCV，低成本打包与校验不再启动 FFmpeg、Paddle 或 OpenCV。

## P2 盲回放

实验范围为 P2《第1话 生意经与招财宝》`00:00–03:50`，使用独立上下文的 `gpt-6-luna`。这段同时包含明确姓名框、主角上下文对白、背景误识别、逐字显示残片和世界观长句。轻量模型被禁止读取人工审核稿与正式 Canon。

| 指标 | 结果 |
| --- | ---: |
| 台词 | 31 |
| 紧凑包字符数 | 14,626 |
| 纯文本路径 | 12 |
| 风险图片路径 | 19 |
| 自动候选 | 22（70.97%） |
| 疑难升级 | 9（29.03%） |
| 轻量模型直接判断的保留/剔除一致率 | 100% |
| 自动候选保留/剔除精度 | 100% |
| 自动候选说话者一致率 | 100% |
| 自动候选文本相似率 ≥ 0.9 | 95% |

9 条升级项中，7 条是画面与上下文支持“主角正在说话”，但轻量模型没有足够依据把视觉主角稳定映射到 `esper-zero`；安全门没有自动接受空 ID。另两条是逐字显示形成的残句，轻量模型主动升级，没有补写缺失文本。

唯一未达到 0.9 相似度的自动文本是薄荷介绍维特海默塔的长句。回看原帧后确认轻量模型保留了画面中的停顿与“乱七八糟”原话，旧人工稿进行了语义整理；该差异不是低模型编造。正式数据没有因此被修改。

第一次试验响应使用了协议未列明的近义内容类型，被严格校验拒绝。Prompt Version `1.1` 补全所有枚举和安全拒绝原因后，后续两次响应均一次通过 Schema。这个失败验证了未知字段/枚举不会静默进入审核结果。

## 验证

- 视频工具定向测试通过；
- Ruff 通过；
- PowerShell 语法检查通过；
- 输入哈希、最大上下文、响应大小、严格字段、完整覆盖和说话者升级边界已有测试；
- P2 原有 `review-decisions.jsonl`、正式 Scene、Canon Evidence 和三张审核视图均未修改；
- 没有调用项目的 DeepSeek / 聊天 Provider API，没有处理 P3。

## 后续使用

P3 开始时按不超过 40 条台词、20 张风险图片拆包。轻量模型完成常规候选后，高能力模型只处理升级队列。主角视觉身份映射仍保持升级项，直到来源级角色绑定规则单独确认，不为了降低比例而放宽安全门。
