# 剧情视频低成本审核工具、P2 实验与 P3 完整运行

状态：协议 v1 已完成；协议 v2 低 Token 优化已完成离线验收，等待下一分 P 实际模型试跑。

## 实现

视频工具使用低成本审核协议 Version `1.0` 与 Prompt Version `1.2`：

1. `low-cost-pack` 按时间范围生成带输入哈希的紧凑包；
2. 轻量模型只读取包内文本和被风险规则选中的图片；
3. `low-cost-validate` 严格校验响应并分出自动候选和疑难队列；
4. `low-cost-benchmark` 只在已有人工稿的校准数据上计算一致率；
5. `low-cost-plan` 为整个分 P 自动拆出有界连续审核包；
6. `low-cost-finalize` 校验自动路径和高审路径完整覆盖后，才生成正式审核稿；
7. 所有中间产物继续位于 Git 忽略的本地 staging。

PowerShell 入口也按命令加载依赖：只有完整 OCR 才安装 Paddle，审核报告/联络表只加载 OpenCV，低成本打包与校验不再启动 FFmpeg、Paddle 或 OpenCV。

## P2 盲回放

实验范围为 P2《第1话 生意经与招财宝》`00:00–03:50`，使用独立上下文的 `gpt-6-luna`。这段同时包含明确姓名框、主角上下文对白、背景误识别、逐字显示残片和世界观长句。轻量模型被禁止读取人工审核稿与正式 Canon。

| 指标 | 结果 |
| --- | ---: |
| 台词 | 31 |
| 紧凑包字符数 | 14,626 |
| 纯文本路径 | 12 |
| 风险图片路径 | 19 |
| 自动候选 | 22（70.97%） |
| 疑难升级 | 9（29.03%） |
| 轻量模型直接判断的保留/剔除一致率 | 100% |
| 自动候选保留/剔除精度 | 100% |
| 自动候选说话者一致率 | 100% |
| 自动候选文本相似率 ≥ 0.9 | 95% |

9 条升级项中，7 条是画面与上下文支持“主角正在说话”，但轻量模型没有足够依据把视觉主角稳定映射到 `esper-zero`；安全门没有自动接受空 ID。另两条是逐字显示形成的残句，轻量模型主动升级，没有补写缺失文本。

唯一未达到 0.9 相似度的自动文本是薄荷介绍维特海默塔的长句。回看原帧后确认轻量模型保留了画面中的停顿与“乱七八糟”原话，旧人工稿进行了语义整理；该差异不是低模型编造。正式数据没有因此被修改。

第一次试验响应使用了协议未列明的近义内容类型，被严格校验拒绝。Prompt Version `1.1` 补全所有枚举和安全拒绝原因后，后续两次响应均一次通过 Schema。P3 再将 Prompt 升到 `1.2`，加入完整 JSON 响应模板，减少长批次的字段漂移。未知字段、枚举和缺失项仍不会静默进入审核结果。

## P3 完整运行

P3《番外 月光当铺》共 687 条候选，自动规划为 27 个包。第一轮轻量审核自动接受 339 条；第二轮轻量审核把可安全确定的总数提高到 646 条，剩余 41 条才交给高能力模型看图。最终保留 617 条、剔除 70 条，0 条待审。

本地下载、GPU OCR 与审核帧生成共 22 分 19.4 秒；第一轮轻量审核 28 分 16.8 秒。后半段因额度暂停，跨暂停墙钟时间不作为性能数据。模型任务数为轻量 33 次、高能力 3 次；其中高能力视觉复核只处理 41 条残余项，另一次用于结构化知识草案。完整数据、修正项和入库结果见 [P3 实施记录](canon-knowledge-p3.md)。

## 后续使用

本节记录协议 v1 的 P3 执行方式。后续分 P 改用下方协议 v2；协议 v1 命令仅保留用于复现与对照。

## 2026-10-07 低 Token 协议 v2

P3 实际运行显示，协议 v1 的主要成本不是 OCR，而是 27 个审核包全部经过模型、首轮携带 522 张风险图、响应为 687 条完整对象，以及模型任务继承过长开发上下文。协议 v2 改为本地安全放行、100 条一包的无图文本审核、稀疏 change 输出和按需视觉升级。模型任务必须用干净隔离上下文执行。

P1–P3 使用既有最终审核稿离线回放，未调用任何模型：

| 分 P | 源候选 | 本地安全放行 | 本地决定/文本/说话者准确率 | 文本模型候选 | 文本包 | 内容/人物 ID 变化 | 仅状态变化 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| P1 | 215 | 16 | 100% / 100% / 100% | 199 | 2 | 92 | 33 |
| P2 | 365 | 53 | 100% / 100% / 100% | 312 | 4 | 183 | 7 |
| P3 | 687 | 110 | 100% / 100% / 100% | 577 | 6 | 154 | 173 |

P3 v1 的 27 个包、522 张首轮图片和约 401,781 输入字符，降为 v2 的 6 个包、0 张首轮图片和约 135,858 输入字符；输入字符下降约 66.2%，文本任务数下降约 77.8%。旧流程的完整逐条响应为 276,992 字符；v2 在全部原样接受时的稀疏响应下限约 6,963 字符，真实响应只按实际 change 增长。P3 金标准中有 154 条发生剔除、明显文字修订或人物 ID 变化，另有 173 条只把保守的说话者状态细化；后者不必为节省额度强制重现。两者都不等同于未来实际视觉队列，视觉数量要由真实轻量模型稀疏响应决定。

离线回放曾尝试放行“高置信但未知说话者”的台词，文本准确但 P1/P2 说话者一致率不足，因此最终规则只自动放行带 confirmed 角色 ID 的稳定台词。省 Token 不以丢失人物归属为代价。

协议 v2 已完成严格哈希、覆盖、稀疏响应、说话者边界、视觉升级和最终完整合并测试。当前还没有真实模型 Token 账单；下一分 P 只需先跑一个包校准实际视觉队列和额度，再决定是否整集执行。
