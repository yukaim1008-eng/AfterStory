# 剧情视频本地处理工具与 P1 验证

状态：工具 Version `1.0` 已实现，`BV1kqoaBiEVZ` P1 已完成机器抽取和逐条画面复核；没有写入正式研究数据或产品数据库。

## 工具位置与职责

工具位于 `research/character-corpus/tools/video_pipeline/`，负责：

1. 读取标准视频或 B 站桌面端视频/音频分轨缓存。
2. 去除当前桌面端缓存的 9 字节前缀并规范化为标准 MP4。
3. 以 4fps 扫描底部字幕区域，用白字、连续文字行和时序变化筛选候选帧。
4. 使用本地 PP-OCRv5 识别候选帧，并逐候选写入可恢复 checkpoint。
5. 合并逐字显示、相邻重复与两行字幕顺序变化。
6. 只有角色目录中的明确姓名标签，或在固定姓名位置稳定重复出现的标签，才确认说话者标签；电影过场保持 `unknown`。
7. 生成台词、场景草稿、问题队列、报告和严格审核状态。

工具不会直接修改 `scenes.jsonl`、SQLite 或 PostgreSQL。全部运行产物固定写入被 Git 忽略的 `research/character-corpus/local/video-pipeline/`。所有新台词和场景默认为 `pending`；只有全部审核通过时，校验结果才可能成为 `export_ready=true`。当前版本故意没有直接写数据库的命令。

## 可恢复边界

每个分 P 独立保存：

- 输入、Preset、媒体参数与配置哈希；
- 规范化视频；
- 字幕候选帧和时间范围；
- 每个候选完成后立即追加的 OCR checkpoint；
- 可从 checkpoint 无模型重建的 OCR 样本、台词与场景草稿；
- 未确认说话者、低置信度和短句的审核队列。

相同配置重复执行 P1 只需约十秒读取已有阶段并重建结果，不会重复跑 35 分钟 OCR。输入或 Preset 变化时必须使用新的输出目录，避免混用历史结果。

## 抽查结论

跨开头新闻、电影过场、普通对话框、战斗喊话和结尾对白抽查 26 个时间点后确认：

- 清晰正文和姓名框能够稳定识别，长句、中英混合词及大部分专有名词可以保留。
- 逐字显示的短残句、同一句两行顺序变化和姓名括号差异可以在重建阶段合并，不需要重跑 OCR。
- 仍会出现标点、空格、繁简和少量专名错误，需要审核原画面。
- “进入游戏”、教程说明、技能名等底部 UI 也可能进入候选。这些内容保持 `pending`，不得直接当作剧情台词。
- 22 个场景仅按对白时间间隔形成，是审核导航，不是最终 Canon 场景边界。

215 条候选均已结合原视频全画面、姓名框、前后对话和候选字幕截图复核：

剔除项包括开场菜单、背景招牌误识别、逐字字幕的中间态和重复项、战斗技能名及教学按钮。世界内的新闻、报纸和伊波恩传单没有当作人物对白，但以 `system_or_broadcast` 或 `world_document_text` 保留。电影过场只在镜头和称呼能够形成连续证据时标为 `probable`，证据不足时保持 `unknown`。

审核产物仍位于忽略的本地暂存区：`review-decisions.jsonl` 记录逐条决定，`reviewed-transcript.jsonl` 保存修订后的 189 条内容，`review-report.html` 提供全画面可视报告。工具新增 `review-report` 与 `review-validate`，后续分 P 可以复用相同审核方式，不要求直接阅读 JSON。

P1 当前结果没有进入 `scenes`、`evidence`、`traits`、Character Definition 或任何运行时数据。下一阶段可以按分 P 继续生成和审核暂存包；正式入库前仍需从审核稿形成最终场景与人物证据。
