# 下一阶段选择清单

状态：候选讨论记录。用户已委托 Agent 起草并执行 A–E 五阶段方案，每阶段验收后提交；当前执行范围以 [F2 方案](implementation/f2-foundations.md) 为准，以下保留选择依据。

## 当前已明确的顺序

- 用户反馈整体流程已跑通，但不等于完整 V1 或聊天效果已经验收。
- 暂不调整角色性格、不建设角色资料库；现有联调资料保持原样。
- 语音尚未接入，等用户认可聊天效果后再推进；默认手动播放的既有决定保留。
- 性格、素材、主题和个性化发送按钮继续采用可更改数据，当前不要求补全。
- 先看清已固定的规则与基础能力缺口，由用户决定下一步。此前“先做娜娜莉资料和表达”的 Agent 建议未被采纳。

## 已确认的规则，不需重新拍板

完整产品规则只在 [V1 基线](decisions/0001-v1-baseline.md) 维护，以下为定位索引。

| 已确认内容 | 实现含义 | 当前情况 |
| --- | --- | --- |
| 用户、角色实例的数据隔离（基线 §5） | 对话、记忆、状态和音频均有明确归属 | 对话已有所属检查；记忆、状态、音频还没有对应实现 |
| 角色定义与个人经历分开，版本不可直接覆盖（§3、§5.1） | 更新配置不能改写原版本或混入私人经历 | 版本导入校验已做；正式 Canon 更新流程未做 |
| 聊天记录与长期记忆分开（§5.2 第6–8项） | 保存消息不等于提取和召回记忆 | 仅聊天存储和最近成功对话上下文已做 |
| 记忆区分事实/推测，可纠正、删除（§5.2 第7–8项） | 需有来源和用户管理入口 | 行为已确认，数据契约及服务未做；前端仅未启用状态 |
| 短期状态与长期关系分开（§5.1、§5.2） | 关系变化有依据，不展示评分、不按轮数自动升级 | 行为已确认，字段与更新机制未做 |
| 文字先形成，语音独立失败和重试（§5.2 第12项） | 语音故障不能抹掉文字或重复写入记忆/关系 | 文字链路已做，语音暂缓 |
| Provider、领域数据与编排分离（§6–7） | 更换模型或后续编排方式可复用现有能力 | 文本 Provider 已接入；Embedding/TTS 未接入 |

“固定下来”在本清单中指已确认的数据归属、职责与行为约束，不代表算法、字段和参数已经定稿。

## 已有能力与实际限制

- 可运行页面：三位角色选择、聊天、资料、历史、设置；主题与封面可替换。
- 文字链路：真实模型、消息持久化、请求 ID 重试、失败轮隔离、刷新恢复、当前用户会话发现。
- 上下文：默认最近 12 轮成功对话；历史界面每次加载 30 轮。全量数据库历史不会自动全部提供给模型。
- 身份：本机开发身份，不是正式账号系统；浏览器封面、偏好、草稿与数据库聊天分开保存。
- 历史：已有列表和末条预览；无真实创建时间字段、列表分页或完整旧角色版本入口。
- 回复结构：当前只含消息/轮次 ID、文字和 audio_status；情绪、风格、状态变化、记忆候选是规划字段。

依据：[API](../afterstory/api.py)、[数据模型](../afterstory/models.py)、[上下文与持久化](../afterstory/repository.py)、[回复结构](../afterstory/domain.py)、[配置](../afterstory/config.py)。

## 可选的下一阶段（未排序、未授权）

这些是便于用户选择的候选拆分，不是已经确认的实施计划。每项都可先用现有联调资料验证，不要求先建角色资料库。

| 候选 | 可限定的阶段产出 | 还需集中决定 | 验收示例 | 模块 |
| --- | --- | --- | --- | --- |
| A. 会话与历史基础 | 完善真实时间、列表分页和历史定位；保留现有重试/隔离规则 | 本轮包含哪些历史操作，旧版本会话怎样进入 | 多段记录能正确定位，刷新和切角色不串记录 | [工程基础](design/05-platform.md)、[前端](design/06-frontend.md) |
| B. 个人记忆数据与管理 | 明确记忆归属、来源、事实/推测、纠正和删除契约；按范围接通管理页 | 是否先做存储/管理，是否同时做提取召回；删除后如何防止重新引入 | 来源可追溯、纠正生效、删除不误删聊天、不同实例隔离 | [记忆与关系](design/03-memory-state.md) |
| C. 对话上下文与回复契约 | 明确角色定义、成功历史、未来记忆/状态的输入边界，以及回复结果契约 | 是否本轮引入长对话摘要/检索；字段最小范围 | 输入可核对，失败轮不污染上下文，缺少可选能力时仍能文字回复 | [理解与回复](design/02-conversation-core.md) |
| D. 状态与关系的存储边界 | 明确归属、变化依据、持久化和重试规则 | 是否仅定义契约，是否实现更新机制；具体算法仍未定 | 跨实例隔离，重复请求不重复更新，不向用户暴露评分 | [记忆与关系](design/03-memory-state.md) |
| E. 工程维护与排障 | 按需整理诊断、运行停止、数据维护或可重复验证方式 | 从哪些实际使用问题入手；日志/维护工具各自范围 | 故障能定位，验证不污染使用数据，结束不留服务 | [工程基础](design/05-platform.md) |

B 的存储与管理完成不等于自动记忆已经完成；C 的数据契约完成不等于角色理解或表达效果已认可；D 的存储完成不等于关系变化算法已经确定。
