# 记忆召回与上下文选择

状态：2026-09-23 完整待审稿，未授权实现。本文设计事实、经历、持续事项、摘要、连续性笔记和历史原文如何按本轮需要进入模型；不改变 Character Definition，也不把全部记忆每轮发送。

## 1. 目标与边界

召回需要同时做到：找到相关内容、采用最新有效版本、保留时间和来源、不让无关旧事淹没当前交流、在预算不足时稳定退化。

召回只在当前用户拥有的 CharacterInstance 内进行。相同用户、相同角色的另一个实例也不能自动共享。Canon 使用独立来源与读取规则，不进入个人记忆检索池。

模型看到的是应用组装的可信数据块；记忆正文和历史原文仍属于数据，不获得系统指令权限。检索到不等于事实正确，仍需保留用户陈述、推测、假设和场景边界。

## 2. 三条读取路径

每轮不应依赖单一向量搜索，推荐同时使用三条路径：

1. **确定性读取**：当前实例、有效状态/关系、已到期事项、明确指向的事件 ID、当前会话近期原文、连续性笔记。
2. **结构化候选**：按人物、事项类型、有效状态、时间范围、来源会话、主题标签和关键词筛选事实/经历/事项。
3. **语义候选**：用 Embedding 找表达不同但含义相关的候选，再由结构和文本相关性重排。

确定性读取解决“已知应该拿什么”；混合检索解决“用户换了一种说法”。Embedding 不是权限层、真值判断或覆盖规则。向量相似不能绕过实例隔离、删除、修订和时间有效性。

V1 推荐在 PostgreSQL 内使用全文/关键词能力与 pgvector 组成混合候选，Embedding 通过独立 Provider 生成。若 Embedding Provider 不可用，系统仍可用确定性读取和结构化/关键词检索继续聊天，并明确降低远期语义找回能力；不把检索失败解释成“从未发生”。

阶段依赖：M2 先提供同实例、按可靠时间/关键词/消息引用定位的有界原文查找及未覆盖成功轮次补查；M3 复用它查找已有事件候选。M4 在此基础上加入全文、向量及复杂重排，不把旧细节找回或事件去重的首个可用版本推迟到 M4。

## 3. 本轮查询如何形成

召回输入由应用构造，不直接把当前消息原样交给任意检索后端：

- 当前用户消息。
- 当前会话最近完整问答中的未解析指代。
- 与本轮匹配的连续性笔记和未完话题。
- 当前时间、用户时区以及消息中的明确时间表达。
- 已识别的人物、事项、事件、否定和“以前/最近/那次”等时间范围。

第一层使用确定性解析与数据库条件；只有需要扩展同义表达、解析复杂指代或重排候选时才调用模型。普通寒暄不必触发昂贵的远期搜索。

“还记得我上次说的第二个方案吗”优先读取当前话题笔记及其来源；“去年八月那次面试”优先按事件时间和主题过滤；“我现在还是不喜欢突然打电话”同时寻找当前偏好及可能的旧版本。时间条件必须作用在事件发生时间，而不是摘要更新时间。

## 4. 候选生成与硬过滤

所有候选先执行硬过滤：

- 当前用户和实例。
- 当前有效或本轮明确需要的历史版本。
- 未被删除、排除或待重建禁止使用。
- 来源修订符合当前实例可见边界。
- 数据类型和场景允许进入本轮；假设/游戏内容不能混入现实事实。

之后并行取得有界候选：

- 当前相关的开放事项和到期提醒。
- 人物、主题、时间、状态命中的事实与经历。
- 全文/关键词命中。
- 向量近邻命中。
- 当前话题引用的摘要、连续性笔记和原文范围。

异步摘要、事件提取和索引各自有已提交的处理位置及缺口。查询明确指向同实例其他会话，而该会话还有未覆盖的成功原文时，先做有界补查；积压超出上限时不能据现有索引断言“从未提及”，应等待、缩小范围或明确无法确认。

每条路径都有上限并按稳定键排序，防止单一路径返回大量相似结果。候选集合按稳定记忆/事件 ID 合并；同一内容的版本、摘要转述和原文引用不能当作多份独立证据。

## 5. 重排与选择

推荐重排考虑以下信号，不预先固化成公开评分公式：

- 本轮直接相关程度。
- 人物、事项、时间和显式指代匹配。
- 当前有效性及后续纠正。
- 来源明确程度；事实、推测和假设分别处理。
- 重要性理由：用户要求记住、重要经历、持续事项、关系依据。
- 时效性：当前状态和近期计划优先，但不能让旧的重要共同经历永久消失。
- 多样性：避免前几项全部是同一事件的重复表述。
- 使用代价：能用短事实回答时，不必加载一整段原文。

最终选择按“覆盖问题所需信息”停止，不为填满预算继续塞入弱相关内容。排序分数只用于系统内部选择，不作为用户好感度或事实置信度展示。

当候选互相冲突时，选择器不能自行判定真相。把当前有效版本、冲突状态和必要来源一起交给回应层；影响本轮答案时自然澄清，否则避免使用争议结论。

## 6. 上下文包与预算优先级

ContextAssembler 仍负责最终确定性组装，推荐顺序为：

1. 冻结 CharacterVersion `system_prompt`。
2. 通用运行时边界及当前时间/时区。
3. 当前有效的 State、Relationship 和到期/高相关持续事项。
4. 本轮相关的事实、偏好与经历。
5. 相关连续性笔记、分段摘要及定向取回的历史材料。
6. 当前会话近期完整原文。
7. 当前用户消息。

现有角色提示、实例运行数据、历史与当前消息的总体边界不变；新增内容在运行时数据内细分。Definition JSON 不直接逐轮注入。

预算先预留不可牺牲部分：角色规则、当前输入、输出空间和安全余量。其余使用分池上限与动态借用，而不是一个类别无限挤占所有空间：

- 近期完整原文保证对话语气和指代连续。
- 到期事项、当前状态和直接回答所需事实优先。
- 旧经历通常先给短表示，需要精确细节再回读原文。
- 摘要和原文重复时保留信息量更合适的一份，来源指针仍保留。

具体 token、候选数量、近期轮数和软硬阈值由选定模型的窗口及回放评测确定，进入配置而不是写死在领域规则。预算计算必须以模型 tokenizer 或保守估算为准，不能只按 Python 字符数声称安全。

## 7. 什么时候回读原文

以下情况优先回读有界原文及必要邻近发言：

- 用户询问原话、精确日期、数值或是谁说的。
- 摘要存在否定、转折、改期或人物指代歧义。
- 新输入可能纠正旧事实或更新同一事件。
- 关系/状态变化需要核对具体互动依据。
- 候选冲突且原文可能消除歧义。

原文块明确标注为历史资料，保留说话方、实际已知时间、会话和来源范围，不伪装成刚发生的消息。读取有次数和 token 上限；找不到或来源不可用时表达不确定，不根据摘要补造精确引文。

## 8. 两阶段召回与延迟控制

大多数轮次先执行无模型的快速召回：确定性读取、结构化过滤、全文和向量候选、规则重排。候选简单且一致时直接组装。

复杂指代、多个冲突候选或需要原文扩展时，再执行有界的模型重排/阅读。该调用发生在数据库长事务和行锁之外，并有独立超时。读取快照后提交本轮前重新检查回复安全修订和所选来源版本，防止纠正/删除期间使用旧材料；普通后台新增通过独立数据修订刷新下一轮候选，不无条件废弃在途回复。

召回准备不能被放进当前 `Repository.begin_turn` 持锁路径。实施时需要把长耗时准备与短事务预留/提交分开，但保持现有 request ID、lease 和过期结果拒绝语义。

## 9. 缓存、索引与更新

- Embedding 绑定具体内容版本和模型版本；正文未变不重复计算。
- 当前有效版本才进入普通检索索引；历史版本只通过明确历史查询读取。
- 新增、纠正、删除先提交权威数据，再异步更新可重建索引；索引滞后时硬过滤仍阻止失效内容进入模型。
- 查询缓存必须包含实例 ID、普通数据修订、回复安全修订和查询条件；不能只按旧 `context_revision` 缓存，也不能跨用户/实例复用候选。
- 摘要、事件和原文拥有各自索引表示，但共享稳定来源；不能因同一内容出现三种表示就提高可信度。
- Embedding/全文索引是派生数据，可以重建；权威正文、版本和来源不能只存在向量库。

## 10. 失败降级

| 失败 | 行为 |
| --- | --- |
| Embedding Provider 失败 | 使用确定性与关键词候选；记录降级，不阻断无关聊天 |
| 向量/全文查询失败 | 使用当前状态、事项、连续性笔记和近期原文 |
| 原文回读失败 | 需要精确历史时说明暂时无法确认；无关问题继续回答 |
| 重排模型超时 | 使用规则排序的高确定性候选，不加入弱相关或冲突条目 |
| 上下文仍超预算 | 先压缩/减少低优先级候选；达到硬上限沿用等待或可重试失败 |
| 索引版本落后 | 权威数据硬过滤；不得采用已经删除或被替代的候选 |

降级不改变持久化记忆，也不自动关闭事项。系统日志记录路径和耗时，不记录完整私人正文。

## 11. 当前代码对齐

当前 `ContextAssembler` 顺序加载最近更新的最多 20 条有效 PersonalMemory、State/Relationship 和当前会话最近 12 个成功 Turn；没有 token 预算、当前时间、摘要、事项、全文或向量检索。`Repository.begin_turn` 在会话/实例锁内调用上下文构建，并会读取本会话全部 Turn 后截取尾部。

实施需要新增独立 Retrieval/Context Preparation 边界，在持锁前完成可能耗时的候选查询、Embedding 和原文扩展；ContextAssembler 只接收已经有界且通过修订核验的运行时材料。无需重构 Provider 协议，也不能让 Retrieval 直接拼系统提示词。

## 12. 验收

工程测试覆盖：跨实例硬隔离；删除/旧版本不进入候选；关键词和向量候选稳定合并；Embedding 失败降级；索引滞后仍过滤；预算不超限；当前输入和角色提示不被裁掉；同一来源不同表示不重复；修订变化拒绝旧准备结果；Provider 输入顺序正确。

效果回放覆盖：同义改写召回；人物同名不串联；时间范围问题；变化与纠错；远期重要经历；近期无关内容不挤掉目标；精确引文回查；冲突时澄清；依据不足时不作答。对照基线至少包括最近 12 轮、仅滚动摘要和混合召回方案，同时测 token、延迟、错误召回及漏召回。

用户审核重点：V1 是否启用 PostgreSQL 全文加 pgvector 的混合召回；上述上下文优先级；Embedding 失败时允许的降级；复杂问题才调用第二阶段模型重排。
