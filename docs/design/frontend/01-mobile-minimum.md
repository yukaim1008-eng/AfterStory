# AfterStory 移动端最小适配 v1

- 日期：2026-10-22。
- 状态：**移动端 v1 已实现；2026-10-24 手机聊天视图拆分及视觉修正已通过浏览器验收**。真实 iOS Safari / Android Chrome 键盘待设备复核。用户于 2026-10-22 确认视觉方向，并于 2026-10-24 要求先拆手机视图、再改视觉。
- 目标：使用现有手机浏览器完成登录、选择角色、持续聊天、查看历史、管理记忆与设置的闭环。
- 基准：[前端当前设计](../06-frontend.md)、[产品基线](../../decisions/0001-v1-baseline.md)。本方案只调整移动端呈现与交互，不改变 Character / Conversation / Memory 的数据边界。
- 效果图与提示词：[集中评审入口](../../../frontend/design/mobile-v1/README.md)。效果图中的对话、日期和记忆条目均为展示样例，不写入数据库。

## 1. 已确认范围与建议边界

用户先要求移动端最小适配方案与效果图，随后认可方向并授权实现。以下记录已采纳的布局、导航、键盘规则及其验收边界。

采用现有 Vue 网站的响应式界面；同一个网址、同一套账号和后端，手机和桌面各用适合屏幕的布局。本阶段不制作原生 App、PWA 安装流程、离线缓存、推送、语音、新助手工具或新的记忆能力。桌面视觉与业务行为保持现有基准。

实施前现有 CSS 已有部分窄屏规则，但未覆盖完整手机体验。本轮处理了桌面导航与聊天头部重复占高、键盘遮挡输入框、回忆/设置固定高度和嵌套滚动、封面编辑双列布局，以及角色卡依赖 hover 的视觉提示。

已有评测通过代表被测试场景通过，不代表所有真实聊天质量与移动端交互已经验收。

## 2. 页面与导航

普通页面使用底部四项导航：**首页 / 角色 / 回忆 / 设置**。聊天是独立的沉浸页面，不显示底部导航，避免占用聊天和键盘空间。

```text
登录 / 邀请码注册
        ↓
首页 ←→ 角色 ←→ 回忆 ←→ 设置
 ↓       ↓       ↓
 └───── 聊天 ────┘
         ├─ 角色资料
         ├─ 当前角色的回忆
         └─ 场景调整
```

- 首页和角色页可进入聊天；历史入口沿用当前历史定位/继续聊天能力，不增加新会话语义。
- 聊天顶部：返回、角色头像/名称、更多。更多包含角色资料、查看回忆和调整场景，沿用已有动作。
- 返回优先回到本次进入聊天的站内页面；直接打开聊天链接时回到角色页。不无条件使用浏览器后退跳出网站。
- 原生浏览器后退、刷新和旋转屏幕不能意外切换角色、创建实例或丢弃输入草稿。草稿至少沿用当前会话内保存能力；刷新后恢复若现状不支持，应在实现前核实，不能在界面上虚假承诺。
- 当前角色在聊天、记忆和资料页清楚显示；切换角色继续走已有实例选择逻辑。

## 3. 聊天页：本阶段的核心

```text
┌──────────────────────────┐
│ ‹  头像 娜娜莉         ⋯ │  单一顶部栏
├──────────────────────────┤
│           今天 21:42      │
│        今天终于忙完了。   │
│ 娜娜莉                   │
│ 回来啦。先歇一会儿……     │  只有消息区滚动
│                          │
├──────────────────────────┤
│ 想和娜娜莉说些什么…   ↑  │  输入区
└──────────────────────────┘
  安全区 / 系统键盘（显示时）
```

### 3.1 视觉与空间

- 手机聊天使用三位正式角色的竖屏场景素材；其他角色仍回退到现有场景图或封面，用户自定义封面优先。头像、主题色与桌面保持同一来源。
- 消息使用独立的浅色气泡保证文字可读；不再整屏叠加高不透明度白色遮罩，以便看到角色与房间。
- 桌面继续使用原有横版场景和前后景结构。竖屏背景是基于原始场景制作的纯图片素材，不包含文字或聊天 UI。
- 用户消息靠右、角色消息靠左，延续现有回复分段与操作能力；不能因为屏幕变小隐藏错误、重试或记住入口。
- 较长消息自然换行；长链接等不可撑出屏幕。正在生成、发送失败、没有消息三类状态均须有设计。

### 3.2 键盘与输入

- 键盘关闭时，顶部栏、消息区、输入区填满可用视口。键盘打开时，消息区收缩，输入框始终在键盘上方，顶部返回保持可达。
- 手机 **Enter 换行，点击发送按钮发送**；中文输入法选词不触发发送。桌面沿用当前发送偏好。
- 输入框建议 1–4 行自动增高，超过后只滚动输入内容；发送按钮触摸区域至少 44×44 CSS px。
- 保留已有发送中保护与失败重试机制，不重复提交；网络错误时保留用户输入。
- 基础高度使用动态视口单位；不能假设 `100dvh` 在所有键盘场景都足够。实机验证后，必要时局部使用 VisualViewport 调整聊天可见高度，监听随页面卸载移除。
- 刘海、底部手势区与键盘高度分别处理，不重复累计底部留白。登录、记忆编辑等表单在键盘出现时允许滚动到当前输入项和提交按钮。

### 3.3 消息滚动

- 用户本来在底部时，新回复保持跟随。
- 用户正在翻旧消息时不强拉到底部；出现轻量“回到最新”提示。
- 加载更早历史保留阅读位置，避免列表突然跳动；发送自己的消息后定位到本轮。
- 键盘开合、横竖屏变化后尽量保持当前阅读锚点；不能每次 resize 都无条件滚到底部。
- 本轮不改变摘要、上下文压缩和历史保存规则，视觉上少显示内容不代表删掉历史。

## 4. 其他页面逐页设计

| 页面 | 手机布局 | 必须保留的动作与状态 |
| --- | --- | --- |
| 登录 / 注册 | 单列品牌、用户名、密码、主按钮；注册增加邀请码。表单可随键盘滚动 | 登录/注册切换、校验错误、提交中、密码可见切换、粘贴和密码管理器；不在效果图展示真实凭据 |
| 首页 | 紧凑顶栏；约 220–280px 的当前角色场景；第一屏出现“继续聊天”；下方最近回忆与其他角色入口 | 数据来自当前实例；加载/空态不伪造已发生的互动；小屏可滚动，不把所有区域硬塞进一屏 |
| 角色 | 单列可点击角色卡；当前角色更突出，其他角色顺序排列 | 名称、短句、当前状态、进入聊天；轻点即可操作，不能依赖 hover；使用现有真实角色列表 |
| 回忆 | 标题与当前角色选择；原有历史/记忆导航；记忆中保留记忆/事项切换；列表单列 | 查询、筛选、来源查看、编辑/删除、事项创建/关闭等已有能力；筛选收进展开区域，不能把本地筛选冒充服务端全量搜索 |
| 设置 | 现有通用/外观/声音/数据管理用紧凑的 2×2 选择区；下方一次展示一个类别；整页自然滚动 | 字号、动效、外观、账号等已有选项；改密、退出不藏在 hover 内；封面管理入口可见；声音仍显示未启用 |
| 角色资料 | 返回 + 头像/姓名 + 单列资料内容 | 沿用现有版本说明与资料来源；不增加人设编辑器或新的资料字段 |

普通页面建议只保留一个主纵向滚动区；内容底部预留底栏和安全区高度。聊天消息滚动与普通页面滚动分开实现，不沿用桌面所有固定高度。

### 4.1 弹窗与封面调整

- 短确认框居中，例如删除记忆；文案点明对象，取消与确认均可触达，危险操作不只依赖颜色表达。
- 角色更多操作使用底部菜单；大型编辑表单和封面裁切使用接近全屏的面板，自带返回/关闭和保存。
- 封面编辑一次显示一个预览，在聊天/角色卡预览之间切换，下方沿用现有位置和缩放控件。首版不新增双指缩放裁切系统。
- 弹层内部只设一个滚动区；打开时防止背景误滚；关闭后恢复焦点与原页面位置。
- 封面仍遵守当前大小/格式限制。手机上传失败、取消选图、未保存退出都有明确反馈。

## 5. 统一视觉规格（建议值）

| 项目 | 建议 |
| --- | --- |
| 基础评审尺寸 | 390×844；同时检查 360×800、430×932 |
| 页面左右边距 | 16px；极窄屏按可读性收紧 |
| 顶部栏 | 约 56px，安全区另计 |
| 底部导航 | 约 56px，安全区另计；仅普通主页面显示 |
| 正文 / 输入字号 | 手机消息默认 15px、输入框 16px；保留小/标准/大字号偏好 |
| 小标题 / 页标题 | 18–20px / 24–28px |
| 交互热区 | 目标至少 44×44px；图标可小于热区 |
| 圆角 / 表面 | 16–20px、奶白与轻玻璃，沿用角色强调色 |
| 字体 | 手机消息正文使用 Noto Sans SC，霞鹜文楷只用于短签名等点缀；桌面角色回复字体不变 |

必须保留浏览器缩放；长文本、字体放大和减少动态效果设置不得导致按钮消失或横向溢出。弱化手机上的大面积实时模糊与持续动画，减少滚动卡顿。

现有字号偏好为小/标准/大，继续使用三档控件；当前没有独立字体家族选择器，本阶段不增加。手机设置显示实际发送规则，不继续展示只适用于桌面的发送快捷键选项。

| `frontend/src/composables/useAfterStory.ts` | 刷新同一会话时保留手机端正在阅读的旧消息位置；主动返回最新时仍滚到底部 |
| HomePage / CharactersPage / MemoriesPage / SettingsPage / LoginPage | 各自局部窄屏布局；使用现有数据和事件 |

| `frontend/src/design-system.css` | 统一窄屏尺寸、安全区和导航留白，避免堆叠冲突断点 |
| `frontend/index.html` | 加入 viewport-fit=cover 以支持安全区布局 |
| `frontend/tests/pages.spec.ts` | 加入手机视口、竖屏背景、桌面/手机共享会话、交互和短横屏场景；保留桌面回归 |

使用 760px 移动断点；短横屏触控设备还按可用高度进入手机布局。761–1023px 的中间宽度保留紧凑布局并查溢出；首版不另设计完整平板产品。

不新增数据库表或 API；不复制一套手机业务状态，不修改角色版本/实例、记忆归属、登录鉴权。服务端聊天和记忆使用同账号读取；当前保存在浏览器的封面和偏好不自动跨设备同步，不能在本方案中承诺同步。

## 7. 开发顺序与验收

本轮已按以下顺序完成并统一验收。

1. **集中设计评审**：本方案 + 两张效果图，共六个页面/状态；用户认可视觉方向并授权开发。
2. **导航与聊天适配**：手机进入聊天、发送、键盘、历史滚动、错误与返回。
3. **其余页面适配**：首页、角色、登录注册、回忆、设置、资料、弹层和封面调整。
4. **浏览器验收**：移动自动化、现有桌面回归与构建通过；实机软键盘和中文输入法留待设备复核。

| 验收场景 | 通过条件 |
| --- | --- |
| 登录 / 邀请码注册 / 改密 / 退出 | 输入项、错误和主操作可见；密码可粘贴；退出不残留上个账号的数据展示 |
| 角色进入 / 返回 / 切换 | 恢复正确实例；原历史仍在；不因为布局切换新建实例 |
| 长短消息 / 生成中 / 失败重试 | 不横向溢出，不重复发送，失败不丢输入，状态可读 |
| 键盘弹出 / 收起 / 中文选词 | 输入框和发送按钮可见，选词不发送，换行规则一致 |
| 旧历史与新回复同时出现 | 旧历史阅读不被打断，可回到最新，加载更多不跳位 |
| 回忆 / 记忆 / 事项 | 筛选与角色范围明确，来源与操作可达，删除须确认 |
| 封面上传 / 预览 / 保存 / 取消 | 同一页面可完成，按原有存储规则生效，无横向双列挤压 |
| 小屏 / 横屏 / 字体放大 | 360/390/430px 宽无页面横滚；320px 做基本可达性检查；约 844×390 横屏仍可输入 |
| 桌面回归 | 1366×768、1440×900 的布局与主要流程未回退；768px 中间宽度查断点溢出 |

Playwright 的 Chromium 手机视口适合验证布局、点击、滚动和接口状态，**不能替代真实 iOS Safari / Android Chrome 的软键盘测试**。自动化使用 mock/fake 接口，不为验收手机布局调用真实模型。自动化结束关闭本次启动的服务，保留用户自启服务与持久化数据。

手机访问部署地址是独立事项：手机的 localhost 指向手机自己。公开域名、HTTPS 和服务器访问条件仍按部署阶段处理，不在此方案中擅自开放服务端口，也不把未部署的设计当作已可公网使用。

## 8. 已采纳的四项选择

| 选择 | 建议方案 | 影响 |
| --- | --- | --- |
| 产品形式 | 现有 Web 响应式适配 | 复用当前账号、数据和部署；以后再讨论 PWA/原生 App |
| 导航 | 普通页底部四项；聊天隐藏底栏 | 手机功能可找到，聊天留出更多空间；聊天通过返回与更多离开 |
| 角色氛围 | 手机竖屏场景、浅色消息气泡、简洁正文；桌面原视觉保留 | 人物与房间可辨认，长对话仍可阅读 |
| 输入行为 | 手机 Enter 换行、点击发送 | 减少中文输入误发；桌面原设置保持 |

其他像素尺寸、组件拆分和监听清理属于本轮实现细节。
