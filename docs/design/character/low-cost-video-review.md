# 剧情视频低成本审核流程

状态：设计 v1；协议 Version `1.0`、Prompt Version `1.2` 已实现。P2 小段完成盲回放，P3 已用完整低成本流程闭环。

## 目标

后续分 P 继续使用本地 GPU OCR，但不再让高能力模型逐条读取整集截图和长逐字稿。流程把机械处理、常规判断和疑难判断分开，并保证轻量模型的错误不能直接污染正式研究库。

```text
本地 OCR / 合并 / 风险规则
→ 有界紧凑审核包
→ 第一轮轻量模型候选响应
→ 确定性 Schema 与安全门
├─ 自动审核候选
└─ 疑难升级队列
→ 第二轮轻量模型复核
→ 少量残余项高能力复核
→ 确定性合并为正式审核稿
→ 既有正式提升流程
```

## 数据与信任边界

- 本地程序负责 OCR、去重、上下文范围、输入哈希、Schema 校验和路由，不消耗语言模型 Token。
- 轻量模型只读取当前审核包和其中标记 `visual_required=true` 的图片，不读取人工金标准、正式 Canon 或整集 HTML 报告。
- 轻量模型只生成候选文件，不能覆盖 `review-decisions.jsonl`、`reviewed-transcript.jsonl`、Scene、Canon Evidence 或产品数据库。
- 响应必须完整覆盖包内 ID，拒绝未知字段、未知枚举、重复/缺失 ID、错误输入哈希和超过 1 MB 的输出。
- 没有明确姓名框时，轻量模型不能把说话者升级为 `confirmed`；已有 confirmed 说话者也不能被替换。
- OCR 标成 `confirmed` 但只有未映射姓名文本、没有稳定 `speaker_id` 时，安全门先降为 `unknown`；它可以保留台词，但不能把未解析标签当成确认身份。
- 高置信度仍不等于自动通过。大幅改写、未查看要求图片、缺少双重说话者依据、非安全拒绝原因都会进入疑难队列。

## 有界输入

单个审核包最多包含：

- 40 条台词；
- 20 张风险图片；
- 一个连续时间范围；
- 角色 ID 与显示名、相邻台词顺序和必要 OCR 风险信息。

输入按规范 JSON 计算 SHA-256，`packet_id` 同时包含分 P、时间范围和哈希。相同输入可以恢复和复用；输入或 Prompt Version 变化会产生新包，不能混用旧响应。

程序只把以下情况送入视觉路径：未确认说话者、低 OCR 置信度、短文本、相邻重复、疑似残句、中文内部异常空格。明确姓名框且文本稳定的内容走纯文本路径。

## 输出分流

轻量模型的决定为 `approve / reject / escalate`。通过确定性安全门后生成：

- `auto-review-candidates.jsonl`：允许进入最终复核的高置信候选；
- `escalation-queue.jsonl`：需要高能力模型或人工判断的少量问题；
- `validation.json`：覆盖率、自动候选数和正式文件未修改声明；
- `benchmark.json`：只在已有人工金标准的校准数据上生成一致率。

即使自动候选通过安全门，它仍不是正式 Canon。整段完成后继续使用既有审核稿校验和 `promote-video` 不可变提升门禁。

`low-cost-plan` 可以按上述上限为整个分 P 自动规划连续审核包。全部包校验后，`low-cost-finalize` 要求高审文件完整覆盖仍未解决的 ID；缺失、重复、越界或错误字段都会阻止生成正式 `review-decisions.jsonl` 与 `reviewed-transcript.jsonl`。

## 模型使用策略

轻量模型负责常规字幕修正、内容类型、明确姓名框、背景/UI 排除和保守说话者候选。第一轮疑难项先由轻量模型在更聚焦的上下文中复核；高能力模型只读取第二轮仍未解决的少量条目及对应图片，并负责最终视觉裁决和跨场景知识归纳。

视频工具自身不保存 API Key，也不直接调用外部模型。模型执行由当前 Agent 编排，因此可以更换轻量模型而不改变研究库格式；模型名称记录在响应中用于追溯。

## 验收标准

- 自动候选的保留/剔除精度为 100%；
- 自动候选的说话者一致率不低于 97%；
- 自动候选的文本与人工稿相似率不低于 95%，差异必须可回看画面解释；
- 所有不满足安全门的条目进入升级队列；
- 正式审核文件与研究库在低成本阶段保持不变；
- 正式合并必须覆盖全部候选，并保留自动路径与高审路径的来源标记。
