# 剧情视频低成本审核流程

状态：协议 v1 已完成 P3 闭环；低 Token 协议 Version `2.0`、Prompt Version `2.0` 已实现，并用 P1–P3 人工金标准完成离线回放。P4 尚未开始。

## 目标

后续分 P 继续使用本地 GPU OCR，但不再让高能力模型逐条读取整集截图和长逐字稿。流程把机械处理、常规判断和疑难判断分开，并保证轻量模型的错误不能直接污染正式研究库。

```text
本地 OCR / 合并 / 风险规则
→ 明确姓名框 + 高置信完整文本由本地规则放行
→ 其余内容进入无图、稀疏输出的轻量文本审核包
→ 未修改项只返回 reviewed_ids，不逐条重复完整对象
→ 拒绝、无法判断和大幅改写项进入视觉队列
→ 少量残余项高能力视觉复核
→ 确定性合并为正式审核稿
→ 既有正式提升流程
```

## 数据与信任边界

- 本地程序负责 OCR、去重、上下文范围、输入哈希、Schema 校验和路由，不消耗语言模型 Token。
- 第一轮轻量模型只读取当前自包含文本包，不读取图片、人工金标准、正式 Canon、整集 HTML 报告或项目开发对话。
- 轻量模型只生成候选文件，不能覆盖 `review-decisions.jsonl`、`reviewed-transcript.jsonl`、Scene、Canon Evidence 或产品数据库。
- 响应用有序 `reviewed_ids` 完整证明覆盖，只在需要修改、拒绝或升级时写 `changes`；拒绝未知字段、重复/缺失 ID、错误输入哈希和超过 500 KB 的输出。
- 没有明确姓名框时，轻量模型不能把说话者升级为 `confirmed`；已有 confirmed 说话者也不能被替换。
- OCR 标成 `confirmed` 但只有未映射姓名文本、没有稳定 `speaker_id` 时，安全门先降为 `unknown`；它可以保留台词，但不能把未解析标签当成确认身份。
- 高置信度仍不等于自动通过。大幅改写、未查看要求图片、缺少双重说话者依据、非安全拒绝原因都会进入疑难队列。

## 有界输入

协议 v2 单个审核包最多包含：

- 100 条待审台词；
- 每条待审台词前后最多一条去重上下文；
- 0 张图片；
- 紧凑时间、OCR 置信度、已有说话者状态和风险原因。

输入按规范 JSON 计算 SHA-256，`packet_id` 同时包含分 P、时间范围和哈希。相同输入可以恢复和复用；输入或 Prompt Version 变化会产生新包，不能混用旧响应。

本地规则只放行“已有明确角色 ID、说话者为 confirmed、OCR ≥ 0.95、完整标点且无风险”的台词。P1/P2 回放证明，单凭高 OCR 放行未知说话者会损失归属信息，因此未知说话者即使文字很清楚也继续进入文本审核。文本审核可以根据包内已确认相邻说话者给出 `probable/ambiguous`，不能升级为 `confirmed`。

文本阶段提出拒绝、无法判断或相似度低于 0.65 的大幅改写时，程序才生成带 `frame_path` 的视觉队列。这样首轮不会把数百张图片送入模型，但最终剔除仍必须经过看图确认。

## 输出分流

稀疏文本响应的变化为 `edit / reject / escalate`。没有 change 的目标表示模型已逐条检查并接受原文。通过确定性安全门后生成：

- `auto-review-candidates.jsonl`：允许进入最终复核的高置信候选；
- `visual-queue.jsonl`：需要高能力模型或人工看图判断的少量问题；
- `validation.json`：覆盖率、自动候选数和正式文件未修改声明；
- `benchmark.json`：只在已有人工金标准的校准数据上生成一致率。

即使自动候选通过安全门，它仍不是正式 Canon。整段完成后继续使用既有审核稿校验和 `promote-video` 不可变提升门禁。

`lean-plan` 按上述上限规划自包含文本包；`lean-validate` 验证稀疏响应并产生视觉队列；`lean-finalize` 要求本地、文本和视觉三条路径共同完整覆盖全部 ID，才生成正式 `review-decisions.jsonl` 与 `reviewed-transcript.jsonl`。协议 v1 命令保留用于复现 P3，不再作为后续分 P 的默认流程。

## 模型使用策略

轻量模型负责常规字幕修正、内容类型和保守说话者候选。每个任务必须从干净上下文启动，只读取该包的 `instructions.md` 与 `request.json`；不得继承长开发对话或其他分包内容。高能力模型只读取 `visual-queue.jsonl` 列出的条目与对应帧，负责最终视觉裁决。跨场景知识归纳属于后续 Canon 阶段，不与逐条审核混在同一次调用。

视频工具自身不保存 API Key，也不直接调用外部模型。模型执行由当前 Agent 编排，因此可以更换轻量模型而不改变研究库格式；模型名称记录在响应中用于追溯。

## 验收标准

- 自动候选的保留/剔除精度为 100%；
- 自动候选的说话者一致率不低于 97%；
- 自动候选的文本与人工稿相似率不低于 95%，差异必须可回看画面解释；
- 所有不满足安全门的条目进入升级队列；
- 正式审核文件与研究库在低成本阶段保持不变；
- 正式合并必须覆盖全部候选，并保留自动路径与高审路径的来源标记。
