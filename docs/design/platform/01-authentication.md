# 登录系统 v1：部署前设计草案

状态：待用户集中确认账号开放方式、凭据方式和现有本地数据归属；本文件不表示这些取舍已获采纳。

## 目标与边界

AfterStory 的 `User → CharacterInstance → Conversation / Memory / State / Relationship` 归属模型已经存在，所有业务路由通过 `current_user` 取得用户 ID。登录系统只替换该身份来源，并提供账号建立、登录、会话续期、退出与失效处理。角色定义和 Canon 仍可由多个账号共用；每位用户的实例与运行数据继续隔离。

首版面向轻量多用户、自托管部署。语音、第三方账号、复杂个人资料、邮箱通知、组织权限与运营后台不进入本阶段。公网开放注册会直接增加模型调用成本，因此需要单独确认。

## 推荐产品取舍（待确认）

| 决策 | 推荐 | 影响 |
| --- | --- | --- |
| 账号开放 | 管理员在服务器上创建账号；网站不提供公开注册 | 可先安全部署并邀请少量用户，后续可增加邀请码；不能由陌生人自行开户。 |
| 登录凭据 | 用户名＋密码；忘记密码由服务器命令重设 | 不需要邮件服务；用户不能自行找回密码。 |
| 旧 `local-user` 数据 | 一次性把首个管理员凭据绑定到现有 `users.id`，不改实例外键 | 原聊天、记忆、关系和提醒原样保留；命令须在本人核对目标账号后执行，且不可重复绑定。 |

## 建议的最小实现

1. 在现有 `users` 表保留稳定 `id`，增加唯一登录名、密码哈希和账号状态；旧行允许暂时无登录凭据。新增服务端登录会话表，记录随机会话令牌的哈希、所属用户、创建/到期/撤销时间。数据库只存哈希，不存明文密码或原始令牌。
2. 密码采用 Argon2id；登录失败统一错误信息并限制尝试频率。创建账号、重置密码和认领旧数据通过本机命令完成，不向匿名 HTTP 请求开放管理员操作。
3. 登录成功签发随机会话令牌，设置仅同站点可用的 `HttpOnly` Cookie；生产环境必须使用 HTTPS 和 `Secure` Cookie。服务端检查绝对/空闲过期，退出和改密使旧会话立即失效。令牌不写入 `localStorage`、URL 或日志。写操作使用 CSRF 校验。
4. `GET /api/auth/me` 由服务端返回当前账号和前端所需的身份信息；匿名访问业务接口返回 401。`current_user` 从已验证会话取得 `users.id`，Repository、Memory、Conversation 的既有所属检查继续生效。健康检查只报告服务状态，不再向匿名访问者返回开发用户 ID 或模型配置。
5. 前端增加未登录入口、登录、退出与会话过期状态。所有 API 继续使用同源 `/api`；浏览器自动携带 Cookie。只有认证完成后才读取按用户 ID 分区的草稿、偏好和 IndexedDB 封面，换账号或退出时清理内存中的旧账号状态，避免切换瞬间展示旧数据。
6. 开发环境和部署环境都走真实登录；测试通过隔离 PostgreSQL schema 创建测试账号或覆盖身份依赖。`seed` 在正式环境只导入公共角色包，不能把 `DEV_USER_ID` 变成可登录账号或绕过认证。

## 部署关联边界

此阶段可准备同源反向代理、允许的 Host、HTTPS Cookie 配置和生产启动校验，但不会在未经服务器参数确认前直接部署。目前 `TrustedHostMiddleware` 只接受本机 Host，`compose.yaml` 仍使用开发数据库口令及本机端口，`afterstory` 启动器也是本地开发入口；完成登录后仍需单独核对服务器域名、TLS、密钥注入、数据库备份及服务常驻方式。仅通过登录测试不能视为部署验收。

## 验收范围

- 匿名用户无法读取或修改会话、记忆、状态、关系和提醒；登录后只能访问本人数据，伪造用户 ID 无效。
- 登录、刷新、过期、退出、改密失效和换账号均正确；Cookie 属性、CSRF、限速和错误信息经过测试。
- 老 `local-user` 数据按确认的方式保留，迁移升级/回滚在隔离 schema 中验证；不清空真实库。
- 前端登录态切换不显示其他账号的草稿和封面；后端、前端与浏览器测试使用 fake Provider，不调用真实模型。
- Ruff、类型检查、构建和相关测试通过；测试后只停止本轮启动的服务。

安全方案参考：[OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。
