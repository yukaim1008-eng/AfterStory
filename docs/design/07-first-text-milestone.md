# M1：最小后端文字链路

状态：工程实现与 PostgreSQL 验证完成，F1 已完成真实模型浏览器回复与刷新恢复，正式角色表达仍待验收。用户已采纳本阶段前四项取舍，并选择 DeepSeek V4 Flash 作为首次真实文本模型。

## 目标与范围

从本地接口创建角色实例和会话，完成多轮文字回复，并在服务重启后继续原会话。此阶段验证骨架与数据流，不代表完整 V1 或娜娜莉角色效果验收。

建议先用两个明确标为工程测试的原创角色，避免等待娜娜莉资料整理；不更改主角色选择。上下文先使用版本化角色定义和最近对话；长期记忆、关系变化、复杂意图识别、TTS 与前端留在后续阶段。未实现的能力不得生成假结果。

## 模块接口草案

| 边界 | 输入 | 输出与责任 |
| --- | --- | --- |
| 身份入口 | 本地开发配置 | 服务端解析的用户身份，不接受请求正文指定所属用户 |
| Character System | 角色版本、用户身份 | 归属于用户的实例；固定引用版本和剧情进度 |
| Conversation Core | 会话、消息、请求标识 | 加载角色与按序历史，构建上下文并调用 Provider |
| Text Provider | 角色指令、历史、当前消息 | 回复文本或明确的调用错误；可替换适配器 |
| Repository | 受用户与实例约束的数据 | 持久化会话、消息和本轮处理状态 |
| Character Response | Provider 文本 | message_id、turn_id、text、audio_status=not_requested；不伪造情绪和关系变化 |

此处 Character Response 仅为 M1 最小子集；最终情绪、风格、状态与记忆候选契约由相应模块后续扩展。

## 最小数据与接口

数据对象：User、Character、CharacterVersion、CharacterInstance、Conversation、Turn、Message。所有用户对话数据必须沿 Conversation → CharacterInstance → User 校验归属，不能只凭传入 ID 访问。

建议提供角色列表、创建实例、创建会话、发送消息和读取分页历史五类接口，另有健康检查。角色定义从项目测试配置导入版本记录；运行时实例引用固定版本，配置修改不覆盖旧版本。

发送消息输入包含会话 ID、文本和客户端请求标识；用户身份由服务端提供。相同会话及请求标识不得重复写入成功回复；相同标识附带不同文本应拒绝。同一会话只允许一轮处于处理中，冲突请求明确返回稍后重试。

接收后保存用户消息与 processing 状态，在数据库事务外调用模型；成功后保存助手消息并完成该轮。失败保存失败状态，不伪造助手回复；同一标识的显式重试复用原用户消息。进程中断遗留的 processing 需按超时规则恢复为可重试状态，不无限卡住。模型调用无法承诺外部恰好一次，超时后的重试可能重复产生供应商费用，但本地成功回复只能提交一次。

历史读取可展示失败状态；模型上下文默认取成功轮次与本轮消息，避免重复包含失败重试的输入。日志不输出密钥或默认打印全部聊天正文。

## 运行方案建议

Python 后端在本机运行，PostgreSQL 通过 Docker Compose 启动；依赖独立虚拟环境，使用 SQLAlchemy 和 Alembic 管理数据访问与迁移。当前只发现 python、docker、uv 命令存在，尚未验证版本、Docker 服务或数据库可用性。

本地身份先由服务端开发配置提供，默认仅监听回环地址；这不是正式登录系统，也不作为多用户部署验收。测试仍注入不同用户验证隔离。公开或共享服务之前另行完成认证设计。

文本调用先支持显式测试 Provider，再接入用户选定的真实供应商。真实调用失败不自动回落成假回复。具体模型、接口协议、依赖版本在实现时结合所选供应商文档核实。

## 验收

- 按文档启动数据库、执行迁移并启动服务，健康检查通过。
- 两个测试角色使用相同工作流，连续三轮对话能传入对应历史。
- 重启服务后原会话和消息顺序不丢失，可继续回复。
- 跨用户、跨角色、跨实例读取或写入不能串数据。
- 重复请求不会产生重复消息；模型超时、失败及服务中断后可明确恢复。
- 测试 Provider 的确定性检查与真实模型的手动多轮验证分别记录；仅前者通过只能称工程验证通过。

## 实现细节与当前限制

- 模型 API 与 model 作为同一命名配置单元保存；支持多个供应商配置共存，通过 `LLM_ACTIVE_MODEL` 选择激活组。具体配置见运行说明，尚未实现角色级模型路由或并行对比。

- 模型适配器默认对 DeepSeek 禁用 thinking，只返回完整文本；后续模型比较可调整，不代表最终角色说话规则。
- 上下文取当前会话最近 12 个成功轮次；输入最多 8000 字符，输出默认最多 1024 tokens。
- 已保存失败轮的用户消息；若后续已开始新轮，旧失败轮不能重试，返回 `stale_turn_retry`，避免历史顺序错乱。
- 使用会话数据库行锁预留处理权，在事务外调用模型；过期请求由后续发送触发恢复，attempt 标识阻止旧调用覆盖重试。
- 没有正式登录、长期记忆、关系变化、TTS 或前端。M1 Character Response 仅含文字及音频未请求状态。

上述取舍明确后，在本阶段内完成骨架、验证及文档同步；不自动扩展到后续模块。
