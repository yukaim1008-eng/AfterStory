# 分区设计入口

工作方式已确认：先整体分区，模块分别维护文档，相关决策整批讨论，按阶段实施。以下模块划分及实施顺序是当前工作草案，不代表所有细节已确认。

已确认规则以 [V1 基线](../decisions/0001-v1-baseline.md) 为准。每份模块文档维护职责、已确认约束、待设计接口、待定问题和验收方向；开始该模块时再细化，避免提前填满所有实现。

| 分区 | 文档 | 职责 |
| --- | --- | --- |
| 角色系统 | [角色与原作资料](01-character-system.md) | 定义、版本、剧情进度、实例与角色素材 |
| 对话核心 | [理解与回复](02-conversation-core.md) | 上下文、意图理解、回应策略和结构化输出 |
| 记忆与关系 | [记忆、状态和关系](03-memory-state.md) | 个人记忆读写、短期情绪与长期关系 |
| 语音层 | [语音与音频](04-voice.md) | Voice Profile、TTS、失败重试与音频生命周期 |
| 工程基础 | [后端与数据边界](05-platform.md) | API、持久化、隔离、配置、Provider 和运行验证 |
| 前端体验 | [前端](06-frontend.md) | 整套桌面静态稿已交付，按用户要求集中反馈、统一修改；角色选择与封面整体已认可，未授权开发 |

记忆与关系属于 Conversation Core 的配套能力；工程基础与前端是支撑分区，不改变三个核心领域。

## 建议的阶段顺序

当前阶段范围和实现结果见 [M1 最小后端文字链路](07-first-text-milestone.md)，启动步骤见 [运行说明](../running-m1.md)。M1 已通过工程验证，真实模型调用待本地密钥。

1. 先设计最小链路需要的接口、数据归属、运行方式与验收条件。意图识别及说话规则保留可替换边界，不要求先完成最终算法。
2. 搭建后端最小文字链路：加载测试角色与实例 → 接收文字 → 调用文本 Provider → 保存并返回回复 → 重启后恢复会话。测试替身只验证工程连通性，不能算真实角色效果验收。
3. 分别完善记忆、关系与角色理解能力，用具体对话案例验证；并准备主角色经过确认的资料。
4. 接入独立语音链路，验证失败降级、重试和隔离，完成后端核心验收。
5. 前端已获准提前独立设计，当前按已认可的 03 版方向逐区细化；用户明确同意开发且所需后端能力明确后，再实现 Vue 页面。

实际开工前只补齐当前阶段必要的取舍；不要求用户一次确定所有模块的全部细节。长期运行的 Agent 循环适合执行有边界的阶段任务，不能替代模块设计与效果验收。
