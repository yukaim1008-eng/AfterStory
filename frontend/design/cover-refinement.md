## 本轮提案

本轮已交付并获认可的 [封面操作四状态稿](../../data/design-preview/cover-refinement-v02.png)，通过内置 imagegen 基于 03 版辅助页面生成；[完整提示词](cover-refinement-v02-prompt.txt)。人物为生成式设计示例，具体像素与真实素材裁切仍需校正。

预览已改为聊天、展开、收窄三种较高画幅，替代旧稿矮横条。图中 2:3、1:1、9:16 仅为生成示意，并非固定响应式规格；左侧裁切框仍偏纵向，后续需随编辑用途和真实容器切换。面部更容易检查，但收窄状态耳部仍需结合正式素材校正，不能直接把本图当作裁切算法验收。

| 场景 | 本轮建议 |
| --- | --- |
| 裁切 | 固定目标比例，拖动图片或缩放；聊天与角色选择分别保存位置。角色选择预览同时包含展开、收窄两种宽度，不再用矮横条代替卡片 |
| 重置位置 | 只重置当前编辑标签的裁切草稿，不更换源图、不立即保存 |
| 保存成功 | 同一保存操作提交源图及两个用途的裁切；成功后关闭调整窗口，在外观页提示“封面已更新” |
| 恢复默认 | 先展示当前/默认封面对比；确认后恢复当前角色的默认图片及对应默认裁切，不影响聊天记录、角色资料或主题 |
| 恢复失败 | 当前封面不变，确认窗口内说明失败，允许重试或取消；不提前显示默认图已生效 |
| 已是默认 | 恢复默认操作不可用并显示“已使用默认封面”，避免无意义确认 |

保存成功只表示全部封面配置已保存，不允许一个用途成功另一个失败却提示整体成功。具体实现需后端/本地持久化契约支持，当前尚无接口承诺。

## 图片与保存边界

- 更换、调整、恢复只针对当前用户正在设置的角色封面，是本轮建议作用范围；多用户/角色配置保存方式待契约设计。
- 错误时保留当前图与编辑草稿，取消不写入。恢复默认只解除自定义展示选择，不在本轮承诺删除原上传文件；文件清理策略另行确定。
- 图片加载失败、格式或大小不支持时，阻止进入可保存状态，保留旧封面并允许重新选图。具体限制未指定，不任意写死上传容量。
- 默认角色图变化不应自动覆盖已保存的自定义封面；默认资源版本及更新策略待实现前明确。
- 本轮只有静态图，不把裁切算法、错误处理或保存操作当作已实现。
